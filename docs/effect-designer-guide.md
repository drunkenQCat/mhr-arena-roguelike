# 商品效果配置说明

这是新效果系统的实验说明。四种内建效果支持单人及固定队伍联机测试；联机效果事务已通过同机双引擎实测，使用模拟 Steam 身份。不同电脑的官方 Steam、3／4人新效果事务及长局尚未验收。全队必须安装同一实验包并重启游戏；不要只替换网页或 Lua。

## 从哪里开始

先启动游戏并进入村庄，在电脑控制台点击“更多工具 → 策划工作台 → 商品效果”。如果看不到效果目录，请确认已完整安装实验包并重启游戏；只复制网页文件不够。

## 配置一个商品

1. 先点“载入游戏配置”，再点“新增效果商品”，或选择已有商品后“复制商品”。
2. 输入玩家看到的名称、价格，选择中文效果。效果会提供说明、单位、数值范围和默认值；不需要填写 Lua 文件路径。
3. 设置允许购买的阶段、开放层数、武器限制、互斥组和限购。武器不勾选表示不限。
4. 设置效果组的叠加方式与总上限。复制或改名不会分出新组；预订和已经生效的量一起占用上限。超出时拒绝购买，不会少给效果却照收全价。
5. 用“规则预览”模拟不同层数、武器、可用 PT、已有增益和预留量。预览不会扣 PT、发物品或改变抽取随机序列。背包容量等原生条件仍须进游戏验证。
6. 点“校验并提交到游戏”，阅读回执。上架商品若效果缺失、版本不兼容或参数非法，会阻止提交；可以先下架并保留草稿。

效果规则在**下一局**生效，包括效果商品的价格、参数和购买条件。当前局与已接受订单使用原规则；看“本局与草稿”对照，不能把提交成功当成本局已换值。

## 四种内建效果

| 效果 | 交付与核验 |
| --- | --- |
| 攻击加成 | 下一完整波次增加固定攻击加成字段；不是固定伤害，也不是攻击百分比 |
| 防御加成 | 下一完整波次增加固定防御加成字段；不是减伤百分比 |
| 发放道具 | 立即发入道具袋，核验数量；可以搜索中文道具名 |
| 装备抽取 | 立即从指定档位奖池抽取，新增本局临时装备；奖池内容在“装备与成长”配置 |

攻击、防御覆盖顺序双怪的整个波次；第一只死亡不会结束效果。猫车后等待原生角色恢复再重新绑定，不重复扣款。原商店同类攻击／防御强化与新效果商品互斥，不能同时让两套系统修改同一字段。

## 实机测试与订单

从“当前局”正常开局，再到“效果商店与订单”购买。这里会真实使用本局 PT、发放物资或修改属性，测试按钮不是无副作用的预览。

- **等待生效 · 可取消**：只预留 PT，尚未扣款。取消会释放预留和限购名额。
- **已锁定**：已经选波，不能取消。场地及角色就绪后应用、读回，再扣款。
- **生效中**：达到了声明的核验等级。属性读回不等于最终伤害承诺。
- **确认未交付**：不扣款。可确认放弃，再重新检查准备。
- **交付待核实**：不要反复购买、退款或重置脚本。先点“只读核实交付”；无法归因时保留待办。
- **恢复待办**：不能开始下一波。安全阶段可“核验并清理”，也可结束本局。

余额分开显示，例如“可用120 PT · 待生效预留30 PT”。所有商品都不能动用已预留的钱。

初次入场的效果未核验前，场地和玩家可继续载入，但战斗操作与怪物更新暂不放行。失败时按订单提示处理，再点“重新核验并继续”；也可停止本局。清波清理失败不会静默带入下一波。

## 多人购买与开战

房主选好入场波次、全队完成准备后，可以购买商品条件允许在整备阶段购买的效果。后续在清波、集结后的选波阶段购买；剥取阶段是否开放，取决于该效果和商品的阶段设置。

每人用自己的 PT 付款、在自己的游戏引擎获得效果。全队限购只限制总购买次数，并不表示全队获得强化；最后一个名额按房主确认顺序决定。取消须等房主和本机确认完成，名额才释放。网络确认期间按钮暂不可用，不要反复点击或 Reset scripts。

下一波强化由房主冻结许可，各端在原生角色就绪后实际应用并读回。包括没有购买的成员在内，全队都确认准备完成才开放战斗。顺序双怪共享完整波次，第一只死亡不清除强化；同时双怪全部结束后才清理和结算。

如果某端断线、队伍或房主改变，本局会停止接纳新效果事务。交付未知的订单保留待办，不因超时自动退款或重发。可安全结束本局，回村恢复原资源并执行“原生保存并确认恢复”。重置脚本不会自动重放旧许可，也不能代替保存恢复；尚不支持运行中重新接管旧多人效果会话。

仍无法核实的订单不必把玩家困在任务里。安全结束、回村，等待原装备与背包恢复，再点“原生保存并确认恢复”。恢复完成后封存义务，保留原交付历史，不伪造购买成功或补扣。

## 把修改交给别人，以及回退

点“导出预设”得到 JSON，发给测试组织者或开发者即可，不需要 Git。这是**完整配置**；接收者应先导出自己的旧配置，再导入、核对差异和校验提交，避免覆盖其他人的规则。

回退时导入之前备份的 JSON，校验提交并开始新局。已经成交的订单仍按原参数处理。JSON 不包含效果脚本代码；新增 Lua 能力由开发者随匹配版本的包提供，缺失实现的商品不能靠导入 JSON 修复。

反馈时记录商品名、预期效果、订单显示、实际数值、发生阶段，再到“帮助与连接”下载测试日志。不要删恢复记录或用连续重置掩盖未知交付。
