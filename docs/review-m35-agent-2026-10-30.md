## 发现

### P1：恢复记录写盘失败仍报告成功

位置：`src/game/equip_wear.ts:228`、`:349`。

`rejson.dump_file()` 的接口返回 boolean，但 `persistStartupState()` 不检查返回值，并捕获异常后不向调用者传播。`appendGrantedEntry()` 外层 try/catch 因而无法感知失败，仍返回 true。实测 mock 写盘返回 false 时，append 返回 true。

此外开局是在换装、清包之后才保存恢复记录；首次保存失败或此前中断，会留下已变更装备/背包而没有可靠恢复记录。抽取也会在发货后漏记清理条目。

应让持久化结果可验证，先保存可恢复的原始状态，再执行变更，并逐步更新事务阶段；写入失败不能静默视为安全完成。

### P1：清理忽略实例定位，可能删除玩家自有的同型号装备

位置：`src/game/equip_wear.ts:405`；失败回滚也在 `:277` 使用相同查找。

虽然持久化了 `boxIndex`，删除时却只用 `idVal + idType` 搜索第一个同型号条目。若装备排序、后续取得同型号装备，或恢复重试时先前临时实例已经删除，查到的可能是另一个实例。mock 中玩家副本在槽 0、临时副本在已记录槽 1，恢复实际删掉槽 0。

应按记录实例定位并验证身份，排序会改变槽位时需额外的稳定标识。每个已删除条目必须及时从待办清单移除，删除失败须保留明确待办；不能用同型号搜索代替实例验证。

### P1：清包部分失败会丢失自动恢复义务

位置：`src/game/pouch_backup.ts:111`–`:128`、`src/game/equip_wear.ts:337`–`:341`、`:419`。

`beginPouchIsolation()` 可能已备份并清掉 Normal，然后在清 BulletBottle 时抛错。模块刻意保持 `isolationActive=true`，要求之后 end 恢复；上层却把 `pouchReport.ok=false` 记成 `pouchIsolated=false`，只返回非阻断警告继续开局。局末 `restoreStartup()` 因这个 false 跳过背包恢复并清空状态记录。

应区分“隔离完全成功”和“已产生变更、必须恢复”，发生部分失败时恢复责任不能消失。此项由代码路径确认，未在游戏中制造故障。

### P2：单轮增益被绑定到整场原生任务

位置：`src/game/buff_service.ts:95`–`:110`，`src/game/main.ts` 的 `buffs.tick(session.readingSnapshot)`。

BuffService 只看 quest.playing / quest.unique，不接收波次身份或清波通知。默认 inPlace 下一层继续使用同一个原生任务，故攻防会心增益不会在层间消耗，而会跨层保留并继续累加。这不符合计划中“仅下一轮有效”的约定。回退 reentry 又会清除，导致两条路线效果不同。

应绑定波次 token，在该波实际开始时启用、清波或取消时消耗。不能把整个原生任务的生命周期等同于一次肉鸽波次。

### P1：会心 hook 依赖 getter 调用顺序，结果可漂移

位置：`src/game/buff_service.ts:158`–`:160`。

`lastCritSet` 保存上次返回值，再进入下次返回公式。相同输入 weaponCrit=0、playerCrit=30、增益=10，连续两次返回分别为 -20、-40；现有测试只调用一次 getter，没有覆盖此问题。getter 可被界面、预览或重算重复读取，不能假设每次读取后 playerCrit 都同步吸收上次结果。

应从稳定基准计算增量，验证对玩家实际武器生效以及重复读取、切武器、技能变化下的稳定性。文档也明确会心 hook 尚未实机验收，却已在商店开放；“M3.6 通过”应拆成各服务的独立验收状态。

## 其他需补的验证

- `endPouchIsolation()` 注释称对齐备份和恢复后的总量，实际只拒绝 bagTotal===0；返回 null 的备份会被认作空备份，读取失败 bagTotal=-1 也会通过。因此现有成功回执不能证明物资完整恢复，应按物品 ID/数量验证并区分未知与空。
- 抽取已有装备会直接复用并扣 PT，但模块没有负责让任务内玩家实际换上它；“发进装备箱”与“局内装备成长可用”需要分开验收。
- 开局/恢复文件没有角色或存档身份校验，跨角色运行需要另行保护，不能仅靠 active 标志恢复 pack 索引。
- 当前主测试的新增 mock 主要覆盖成功路径。应补写盘失败、部分清包、重复恢复、同型号多副本、跨波增益和会心重复读取，再做正式流程复测。

建议先修恢复相关三项，再开放会心并校正增益按波次消耗。没有必要为此次审查操纵角色或重复结算实验。
