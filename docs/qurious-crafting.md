# 原生防具傀异炼化

本功能使用《曙光》原生防具炼化算法与装备结果结构。网页入口在「本局装备库」的防具详情。武器炼化不在本次范围内。

## 玩家流程

选择本局临时大师位防具 → 选择通常 / 安定 / 技能 / 孔位模式 → 支付 60 PT 生成 → 对比当前与接受后的能力 → 接受叠加或保留原状。生成费用不退；正在确认结果时暂停换装和镶嵌。

上位防具不支持原生炼化，界面会提示原因。默认高级和终极装备池加入雪鬼兽X五件防具；现有玩家配置不会被静默覆盖，需在策划配置中更新对应奖池。珠子库存和镶嵌规则保持独立。

## 原生调用与叠加边界

- `ArmorCustomBuildupData.createResult`：原生随机生成，模式编号为通常 0、技能 1、孔位 2、安定 3。
- 生成依据使用当前实际生效的技能与孔位，防止反复移除已经不存在的技能。
- `EquipmentInventoryData.setCustomStartup`、`setCustomBuildup`：在独立装备副本中预览，确认后写入本局登记的装备。
- 结果数组固定初始化七个非空结果对象；未使用的位置也必须初始化。
- 将等效的防御、耐性变化合并为原生数值表中可表示的条目；保留技能与孔位变化的完整代价。
- 合并可能改变原生预算，故必须再次执行 `checkCustomBuildUpCheat` 与 `checkCustomValid`。首次生成在容量允许时可保留原始编码作为后备。
- 超过七项或未通过原生检查的候选不能接受。不扩容数组、不关闭原生检查，不支持无限叠加。

候选持久化到本局装备恢复记录；确认前同时登记装备指纹的前后两个合法端点，确认后更新指纹及穿戴快照。所有装备写入在 `EquipDataManager.update` 回调执行。HTTP 命令沿用会话、波次、装备版本和请求去重检查。

原生装备切换使用独立 `PlEquipPack`，应用后调用 `convertRefToVariable` 同步真实穿戴索引，再验证引用，避免以预先改写的 live pack 充当切换结果。

## 2026-11-13 Instance2 验证

独立分支：`feat/native-qurious-crafting`。仅向 Instance2 部署 Lua 与网页，未修改 Instance1。测试使用备份后的初始存档；无需永久解锁傀异系统。Instance2 专用演示配置使用雪鬼兽X初始防具和 1500 PT，属于验证配置，不是玩家默认平衡。

- 四种模式均通过原生生成、预览、PT 扣款、接受及装备数据回读验证。
- 孔位特化成功连续接受两次；第二次前有三次候选未通过原生检查并被禁止接受。
- 实测雪鬼兽X腕甲第二次接受前为防御 101、孔位 4 / 1，接受后为防御 104、孔位 4 / 1 / 1，同时移除拔刀术【力】Lv1，保留特殊射击强化 Lv1。
- 在实际任务角色 `snow.player.LongSword` 上读取到特殊射击强化 Lv1，以及挑战者 5、怨恨 5 等装备技能。未以单独的 `PlayerData._Defence` 字段作为最终防御验收。
- 测试局结束后，全箱 21 件原装备指纹和原穿戴索引与开局前一致，临时防具已回收。存档另有完整备份；用于验证的中间存档和恢复记录也保留归档。
- 512 项单元 / 合约测试、19 个 Vue 渲染场景通过；新增原生边界测试覆盖结果数组初始化、容量溢出和原生检查拒绝。构建与 Lua 语法检查通过。
- 浏览器视觉验收因自动检查无法可靠确认 URL 而中止，不能写成已完成网页实机点击验收。

实测数据的可视化快照见 [qurious-result.html](qurious-result.html)。原始探针与回执保留在本地 `docs/evidence/2026-11-13-qurious/`，按仓库约定默认忽略。

仍需专项验收：战斗伤害 / 减伤数值、多人技能同步、长时间运行以及炼化确认中断后的存档回归。当前为开发分支功能，不代表正式多人发布验收完成。
