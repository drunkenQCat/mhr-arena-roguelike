# 玩家使用说明（Windows / Steam 联机多波次实验版）

## 先看这几句

这是《怪物猎人：崛起》的斗技场肉鸽测试模组，需要 Windows 10/11、Steam 游戏和 Sunbreak 内容。本次增加了独立的联机入场实验入口，详细步骤见同包《测试与反馈》。已接入联机局内选波、出怪确认、PT 与购物；本机双真实引擎已通过多波次、个人购物、共享猫车与失败回村；本地模拟 Steam 传输不能替代不同电脑官方 Steam 验收。网页控制台是游戏的遥控器，手机不是第二个游戏客户端。开发用 p2/p3 也不是真正的联机队友。

当前版本用于招募测试和收集问题，不承诺完整多人、长局稳定性或装备恢复的全面验收。先备份存档，使用愿意承担实验风险的角色。朋友联机请按同包《测试与反馈》，只用“联机大厅”进入约好的私人大厅；单人开局不能用于联机。

你不需要安装 Node.js、Python、Visual Studio 或 Vite。下面的安装面向已经下载好的发行 ZIP，不是 GitHub 的 Source code.zip。

## 一、准备和备份

1. 在游戏中正常保存并退出，确认游戏已完全关闭。
2. 在 Steam 库中找到《MONSTER HUNTER RISE》，右键 → 属性 → 已安装文件 → 浏览。打开的目录中应直接看到 MonsterHunterRise.exe。这就是下文的“游戏目录”。
3. 先备份你的游戏存档。Steam 常见位置为 Steam 安装目录下 userdata → 一串数字的账户目录 → 1446780。退出游戏后把整个 1446780 文件夹复制到一个带日期的备份目录；多个账户目录时先确认对应自己的账户，不要删除或覆盖原文件。Steam 云同步不能替代独立备份。
4. 如果以前装过 REFramework 或本模组，再把游戏目录中的 dinput8.dll、reframework 文件夹、reframework_pictographic.mode 单独备份。其他模组可能共用这些文件。

## 二、安装发行包

1. 找到下载的 MHR-Arena-Roguelike-版本号.zip，右键 → 全部解压缩。不要直接在压缩包窗口里启动文件。
2. 打开解压出来的文件夹，将“里面的内容”复制到游戏目录，而不是把整个外层文件夹套进去。
3. 安装完成后应是：

   MonsterHunterRise.exe（游戏原有）
   dinput8.dll
   打开电脑控制台.url
   使用说明.txt
   测试与反馈.txt
   build-manifest.json
   reframework/autorun/mhw_rogue.lua
   reframework/plugins/webconsole.dll
   reframework/plugins/console.html
   reframework/data/mhw_rogue_config.json

4. 如果 Windows 询问是否替换同名文件，先确认已做上一步备份，再替换本包对应文件。不要整体删除已有 reframework 文件夹。
5. 从 Steam 正常启动游戏，选择存档并进村。第一次加载可能比平时慢一些。

本包内置了匹配的 REFramework fork。不要为了“更新”单独换成任意上游版本，否则后端运行 Lua/重置脚本等接口可能不可用。无需安装额外的旧任务 JSON、VR 示例脚本或自动探针。

## 三、在电脑打开控制台

1. 保持游戏开启。可以按 Alt+Tab 切到桌面。
2. 双击游戏目录里的“打开电脑控制台.url”。或者在 Edge/Chrome 的地址栏输入：

   http://127.0.0.1:11777/console

3. 注意输入到浏览器最上面的地址栏，不是搜索框。127.0.0.1 的意思是“当前这台电脑”，只有电脑自己能用这个地址访问自己的游戏。
4. 页面显示“已连接游戏”后，在“当前局”中选初始防具、点击开始，再选本层任务。
5. 如果地址能打开，但提示游戏状态过期，先回到游戏查看是否还在加载或结算；页面打开不等于游戏已经准备好。

控制台与游戏同启同停。不需要另外开服务器，游戏关掉后页面断开属于正常现象。

## 四、可选：单人肉鸽功能回归（联机测试跳过此节）

- Single：一只怪。
- Sequential：两只怪顺序出场，第一只结束后再出第二只。
- Simultaneous：两只同时出场；相同组合下，相比顺序波次奖励更高、单只血量/伤害略降。
- 击败本波全部目标后，等待剥取时间，回到这场任务刚入场的起点集结。并不是“返回村庄”。
- 集结完成后，网页商店才允许正常购买，再选下一波。购买显示排队时先等结果，不要连点。
- PT 是这局模组使用的点数，不是游戏金钱。按页面显示的价格和余额购物。
- 要结束，使用网页“结束本局”，并回游戏完成原生结算。背景截图页若提示“F 前进”，按 F 继续；后端可能将该页显示为 unknown，不要因此认定存档或角色丢失。
- 返回村庄，等待页面的装备/背包恢复完成，再关游戏或开下一局。恢复待处理时不要重置脚本、删备份或反复开局。

## 五、用手机遥控：跟着做即可

“局域网”在这里就是家中同一个路由器连起来的设备。

1. 手机连接家里的 Wi-Fi。电脑连接同一个 Wi-Fi，或者用网线插在同一个路由器上。
2. 手机只开移动数据不行；连访客 Wi-Fi、学校/公司/酒店隔离网络也可能不行。
3. 先在电脑确认控制台能打开，再切到网页“帮助与连接”。
4. 该页会列出类似下面的手机地址：

   http://192.168.1.25:11777/console

   上面的数字只是例子，你要使用自己页面列出的地址。每台电脑的数字可能不一样。
5. 在手机浏览器最上方地址栏输入完整地址，再按前往。保留 http://、:11777 和 /console。
6. 列出多个地址时，先选网卡名称为 Wi-Fi / 以太网的地址；不要选 VPN。换网络后回电脑刷新列表。
7. 手机不能输入 127.0.0.1，那在手机上代表手机自己。也不要输入 0.0.0.0，它是程序的监听设置，不是浏览器访问地址。

### 页面没列出地址，如何自己找电脑 IP？

1. 在游戏电脑上点“开始”→“设置”→“网络和 Internet”。
2. 使用无线：点“Wi-Fi”→当前连接的网络/硬件属性。使用网线：点“以太网”。也可在已连接网络旁点“属性”。
3. 向下找“IPv4 地址”，记下像 192.168.1.25 这样的数字。
4. 不要记“默认网关”、DNS 或 IPv6；也不要去手机上查。
5. 将自己的数字代入 http://你的IPv4地址:11777/console，在手机浏览器打开。

### 电脑能开，手机一直打不开？

按顺序排查：游戏未关闭 → 同一路由器 → 不是访客 Wi-Fi → 暂时断开 VPN → 刷新电脑 IP → 防火墙。

Windows 默认可能阻止其他设备连进电脑。不要关闭整个防火墙。下面提供一种只放行本机端口、同一子网来源的办法；只在可信的家庭网络上操作。

1. 右键“开始”，选择“终端（管理员）”或“Windows PowerShell（管理员）”，确认系统询问。
2. 复制下面整行，粘贴后按 Enter：

   New-NetFirewallRule -Name 'MHR-Webconsole-LAN-11777' -DisplayName 'MHR Webconsole LAN 11777' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 11777 -RemoteAddress LocalSubnet -Profile Private

3. 若显示已有同名规则，不要反复添加。若提示无权限，确认窗口标题有“管理员”。
4. 该规则仅对 Windows 标记为“专用”的可信网络生效；如果你当前是公共场所网络，不要为此放宽成所有网络，换回家中网络再试。电脑设置的网络属性中可查看当前类别。
5. 回手机重试。公司设备可能由管理员统一限制，请联系管理员，不要修改单位策略。

这行命令的意思：允许同一子网设备连接电脑的 TCP 11777 端口，仅专用网络生效。它不是“开启互联网服务器”，也不需要在路由器做端口转发。

撤销时，在管理员 PowerShell 执行：

   Remove-NetFirewallRule -Name 'MHR-Webconsole-LAN-11777'

控制台当前没有登录鉴权，能访问它的可信网络设备可以操作游戏，也可能调用维护用 Lua 执行接口。不要把地址发布到公网，不要做公网端口转发，不要在陌生公共网络开放服务。

## 六、数值编辑与测试工具

“更多工具 → 策划工作台”适合参与调参的测试者。先导出原配置，再修改；提交后显示成功才算保存。当前波次不会重算，部分规则从下一局生效。不要把未测过的怪物组合当作已经支持。

普通玩家不需要探针。发行包不带自动探针和示例 autorun。维护者需要抓一次状态时，可以通过后端执行一次 Lua，而不是要求玩家长期挂着诊断脚本。

开发测试按钮默认隐藏。在“帮助与连接”→“策划与开发者”中勾选显示后，可以看到无敌、传送和快速击杀；刷新网页后恢复隐藏。这些按钮只用于流程验证，反馈平衡问题时需说明是否启用过。

## 七、更新、卸载与出问题时怎么办

更新：先正常结束并回村，等待恢复完成，完全退出游戏，备份旧配置和存档，再复制新包；重开游戏并刷新网页。不要在一局中覆盖脚本。DLL 更新必须重启游戏，网页刷新不能重载 DLL。

配置：本包自带默认配置，覆盖会重置以前的调参。要保留旧参数先导出，更新后由网页校验再提交，不要盲目把旧版整个覆盖回去。

旧实验脚本：安装新包不会自动删除你以前装过的探针。只移动自己确认属于实验的脚本到 reframework/autorun 之外，保留备份；不要误删其他模组。脚本移出后也要退出重开游戏才停止旧钩子。

卸载：先在村庄完成恢复并退出。只移走本包的 mhw_rogue.lua、webconsole.dll、console.html；保留 reframework/data 中的配置和恢复记录备份。dinput8.dll 可能被别的模组共用，不要随便删除；有旧备份时按原样恢复。恢复未完成时先反馈，不要直接卸载。

无法启动：恢复安装前的模组文件备份，确认游戏原本能运行，再提交测试反馈。Steam 验证游戏文件不一定会删除额外安装的模组 DLL。

网页拒绝连接：确认游戏进程存在、安装层级正确、DLL 已重启加载；电脑先试本机地址。新版“帮助与连接”没有地址列表时，可能仍加载着旧版 DLL。

结果待核实：不要重复购买或反复重置。到“命令记录”导出，附上游戏画面和 build-manifest.json 中版本，按“测试与反馈.txt”报问题。

## 新版启动与一键反馈

游戏启动后会自动用默认浏览器打开 http://localhost:11777/console，每次游戏进程只打开一次，Reset scripts 不会重复打开。未自动打开时可双击安装包的“打开电脑控制台.url”。尚未进入存档时，网页可能暂时显示等待状态。

网页上方的“下载测试日志”会下载一个 JSON 文件；遇到问题，请双方各下载一份并私下发给组织者，附当前游戏截图。文件含版本、状态、操作和有限长度的最近错误，可能含玩家标识和电脑路径；不含存档或密码。游戏仍在运行时才能下载。

“帮助与连接”列出手机访问地址及防火墙排查，并提供测试日志下载。两人联机以“测试与反馈.txt”为准，新版不再手动复制任务码。

## 网页操作与预览

网页默认进入“当前局”，显示阶段、PT、猫车和当前操作；刷新保留所选页面。联机入场成功时，从大厅页自动进入当前局。队友可购物并查看候选波次，由房主选择出战；同步完成不表示队友已买好补给，请先口头确认。结束后展示游戏保留的层数、余额与购买记录，余额不代表累计收益。

“更多工具”包含策划工作台和命令记录。策划侧栏与提交页共享预览层数、人数和解锁条件；层段对照、24 次固定种子抽样与补给购买力用于比较配置，不代表实测难度、精确概率或通关率。


### 恢复记录提示不匹配或损坏

如果网页提示“恢复属于另一个角色”，请回到标题并加载提示中的原角色，不要删除恢复文件或继续覆盖开局。角色名相同也可能属于不同角色，工具会核对原生标识与存档槽。

如果提示“恢复记录损坏”“旧格式需要迁移”或“游戏已重启，临时装备回收需核验”，先下载日志并保留游戏目录 `reframework/data` 中的 `mhw_rogue_startup_state.json` 和 `mhw_rogue_pouch_state.json`，交给维护者核对。当前版本不会凭旧内存地址删除重启后的装备；完整跨进程回收仍在完善，不能通过反复重载脚本解除该保护。文件可能含角色及背包信息，反馈时发给你信任的维护者。
