# 同场长局：原生出怪记录的复用研究与实现步骤

目标是在同一任务中长期续波，并保持个人钱包、装备、奖励与原生联机身份正确。当前实现仍逐次创建 EnemySetInfo，最多允许512项参数索引；任务槽位可复用，不能据此称为无限局。本文是实现任务书，未落地的步骤不属于发布能力。

## 已确认的约束

| 事实 | 代码或原始证据 | 对实现的约束 |
|---|---|---|
| 创建记录后追加到首领记录列表 | 历史原生捕获 `createEnemySetInfo`，地址 `7ff7bf507337–7ff7bf507344`，读取管理器 `+0x410` 并追加新记录 | 当前每次追加会增长列表，销毁actor不等于注销记录 |
| 按ID取记录使用列表下标 | `getEnemySetInfo`：`7ff7c1b0d236–7ff7c1b0d246` 比较Count，再读取 `items[id]` | 删除中间元素会改变后续ID含义；不能直接 `RemoveAt` 压缩 |
| 任务出场槽与记录ID是两套索引 | `src/game/inplace_waves.ts` 将新ID写入可复用任务槽；`prepareInplaceSlot`按EmSetId写数值数组 | 清空任务槽或回收出场游标不能回收参数索引 |
| 参数数组按记录ID访问 | `src/game/quest_installer.ts` 的 `prepareInplaceSlot`；本地旧数值读取反汇编 | 血量、攻击、体型等数组必须覆盖记录ID，不能用任务槽索引替代 |
| 身份包含记录与代际 | 历史反射：EmSetId为Int16、EmGenId为UInt16、UniqueId为Int32；存在 `setEmGenId / updateUniqueId / checkIsNewerGenId / checkIsOldEnemyDestroy / checkUpdateSetStatus` | 应研究引擎的代际更新协议；不能根据UID样本猜公式或只写三个字段 |
| 记录保留网络缓存 | 反射有 `CachePacketList / cachePacket / reflectCachePacket / clearCachePacket`，其中清理存在无参和Int32重载 | 新一代actor必须隔离旧包；不能只验证屏幕上再次出现怪物 |
| reset不是注销证明 | `resetEnemy` 捕获可见其清除OwnerEnemy及actor回链、重置SetupParam标志；没有看到它删除管理器列表项 | 不能用reset返回void或actor消失宣称索引已回收 |

原始捕获位于本地忽略目录 `docs/evidence/2026-10-27-native-flow/`，方法签名还可从 `sdk-dump/sdk_types.json` 查找。地址和偏移只标识该次捕获，不可作为其它游戏进程的硬编码调用地址。`clearEnemySetInfoList()` 在反射中存在，但现有归档没有其实现，尚不能认定它适合局中调用。`clearBossSetAll()` 遍历的是任务首领槽，也不能把它当作逐条记录注销接口。

## 首选方案：保留下标，按原生代际复用记录

### 11月9日补充：当前进程中的身份计算

在运行构建727bdab的P2进程中重新导出反射地址，并仅用ReadProcessMemory捕获原生实现，没有调用下面这些方法或修改记录。原始捕获保存在本地 `docs/evidence/2026-11-09-long-run-native/`。以下伪代码只表达已读到的整数计算，不代表可以跳过加载、缓存和退役协议：

```text
setEmGenId(g):
    EmGenId = UInt16(g)
    UniqueId = Int16(EmSetId) * 100 + UInt16(g)

updateUniqueId():
    g = UInt16(EmGenId + 1) % 100
    EmGenId = g
    UniqueId = Int16(EmSetId) * 100 + g
    clear SetupParam flags through a native helper
```

`updateUniqueId`先作16位递增，随后除100取余；不是用满65536代才回绕。`checkIsNewerGenId`及另外两个新旧状态判断中还出现差值50的比较，但各分支的有符号性不同，不能用普通整数“更大就是更新”替代。`clearEnemySetInfoList`在锁内清理管理器三张记录表并重置分配计数，进一步说明它不是已证明的单条注销入口。

这使固定记录池多出一个明确验收项：同一下标跨过99→0后UID会重复。业务波次token、去重、死亡事件以及原生迟到包必须分别验证；仅检查下一只UID不同不足以证明长期安全。步骤1的成功代际样本仍然缺失，当前保护上限保持512，不把这次只读分析算作记录复用成功。

这一方案保持记录列表长度有界，也保留EmSetId与参数数组下标的关系。前提是证明原生能重新初始化已退役的首领记录及参数；目前没有该证明，不得直接接入玩家版。

1. **先捕获成功的原生代际变化。** 选择原生确实使用同一记录生成新actor的流程，记录 `EmSetId / EmGenId / UniqueId / SetStatus / DestroyStatus / OwnerEnemy / SetupParam / CachePacketList` 前后值，并追踪 `setEmGenId`、`updateUniqueId`、接收setup包和缓存包反映的调用顺序。小怪样本只能说明身份协议，首领路径还要独立核对；不能再次拿小怪复活成功代替首领调度证明。
2. **确认代际规则及调用线程。** 结合上述当前进程捕获，继续核对新旧代比较、SetupParam标志重置及缓存清理的完整调用链。确定99→0、迟到包和generation相等的语义，确认是否需要锁或特定原生update上下文；不能仅靠本次测到的UID单调上升。
3. **建立退役条件。** 仅考虑本模组创建、记录身份匹配的候选项。死亡/捕获成立，剥取等待完成，OwnerEnemy为空，销毁队列已处理，任务槽不再引用旧记录，无待加载/待同步ticket，且缓存和网络引用的退出条件已证明。禁止拿仍有尸体或只是血量为0的记录复用。
4. **预检全部资源。** 为下一怪种准备新的BossSetParam与必要的SetupParam，核对位置、怪种、模板数值和所有按ID索引的数组。确认源模板记录仍在；当前实现通过ID0取得原始参数，首版不回收这条源记录。预检失败不修改候选记录。
5. **让所有端准备同一旧身份与新身份。** 扩展现有SpawnTicket，显式携带旧代与预期新代、记录ID、新UID、怪种、任务实例和波次token。改变wire结构时升级协议并拒绝旧客户端，不静默复用R4含义。每端通过原生入口得到新身份并读回一致后才ACK；房主不能把本机对象地址发给队友。
6. **按已证实协议重新登记。** 使用步骤1–2确认的接口依次更新参数、代际、setup与状态，清理属于旧代的缓存引用，再登记任务槽并进入RequestLoad。不能只调用 `repop()`、强设CreateEnemy，或通过清空整个列表制造空位。确认前不删除旧对象、不释放可能仍被原生读者引用的数组。
7. **处理部分失败。** 全队在激活前任一端失败则禁止生成。只有证明旧状态可完整恢复时才回滚；否则结束当前任务并走已有个人恢复流程。激活后发生不一致，不能单端换另一个记录再试。业务波次token和事务ID保持独立，旧UID的迟到死亡/奖励不得结算新一波。

## 验收必须覆盖的范围

先做单引擎记录复用实验，再做两个真实引擎，最后扩展3/4端。每次至少记录构建SHA、游戏版本、任务实例、旧/新记录ID与代际、UID、actor及参数数组容量；统计按波次或固定时间间隔采集，不恢复常驻大JSON快照。

- 同种与不同怪种复用；顺序和同时双怪；正常讨伐与原生捕获。
- 一端尸体清理更慢、缓存包迟到、重复ACK、旧代死亡事件和旧任务请求；不得误伤新actor或重发奖励。
- 一端准备失败、应用中断、丢包或断线，验证全队停止及原装备/物资精确恢复。
- 普通武器可造成伤害，主从最大HP一致，掉落/钱包/服务保持个人隔离。
- 明确跨过当前512次记录分配边界；稳定池方案应保持记录数、参数容量与活对象数有界，而不是把上限改成更大数字后再跑几波。
- 持续多小时并检查内存趋势；正常代际99→0及异常UInt16输入边界分别做专项。结果记录保存三猫原生Failed、个人保存及不Reset重开，不能用stop替代三猫。

源码测试可验证协议、身份与状态机，但不能证明原生读者已释放旧引用或没有使用旧网络包。通过前保留现有保护与“长局待验证”能力声明。

## 首选方案不能成立时

如果原生记录不能安全重新绑定怪种/代际，则先研究合法的逐条注销入口和全部引用；历史方法列表没有提供已确认的逐条注销协议，不按方法名猜测全表clear的适用范围。

另一条工程路线是全队换图检查点：清波集结后冻结交易，保存固定名册、配置摘要、层数、钱包、限购、临时装备、掉落去重和待消费服务，各端ACK；正常结束原生任务，精确区分“检查点返程”与“整局结束”，重入后重新核对角色身份、配置和原生记录，再延续业务局。需要独立实现持久事务、异常恢复、重连屏障和UI提示；当前通用局末恢复会回收临时资源，不能直接调用stop再恢复几个PT字段冒充该功能。

检查点换图不满足“同场不中断”的字面要求，只能作为明确说明的替代方案，不能为了移除实验标签默认替换既定目标。
