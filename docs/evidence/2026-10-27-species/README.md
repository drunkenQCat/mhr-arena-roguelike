# inPlace 不同怪种与已释放任务槽复用（2026-10-27）

## 场景与操作

同一单人任务 900102，unique 1994278460。原目标镰鼬龙王（98，UID 0）和额外同种怪 UID 11600 已死亡并清理，眠狗龙王（54，UID 100）保留存活。角色全程停留在斗技场起点；没有回村或重新加载地图。主 HUD 在 Reset scripts 后显示 Idle，不能据此认定角色不在任务中。

实验脚本 inplace_species_probe.lua 创建新的 BossSetParam，复制原参数的位置、旋转、区域等字段，但将新对象 _TypeValue 设为 60（青熊兽）；原参数仍为 98。通过 createEnemySetInfo 注册新的记录，写入任务槽和顺序表，再从 RequestLoad(5) 恢复原生加载调度；脚本未直接调用 createEnemyFromSetInfo。

## A：新任务槽加载不同怪种

- 注册时间 1793074345，列表原有 117 条；新记录 EmSetId 117、UID 11700、type 60。
- 使用任务槽 3，顺序索引 3。原生加载后游标变为 4，槽 State 为 1。
- 原生 Boss 列表同时出现 UID 100 / type 54 和 UID 11700 / type 60。
- 定向原生致死伤害后，界面显示“青熊兽 讨伐”；随后尸体清理，槽 3 释放为 State 2 / EmSetId -1。
- 任务未结束，眠狗龙王仍存活。

## B：复用已释放的任务槽

- 使用此前额外镰鼬龙王释放的任务槽 2；创建新记录 EmSetId 118 / UID 11800 / type 60。
- 顺序索引 4 映射到槽 2；原生加载后游标变为 5，槽 2 为 State 1 / EmSetId 118 / EmType 60。
- 原生 Boss 列表同时包含 UID 100 / type 54 和 UID 11800 / type 60。再次执行定向击杀。最终仅剩原眠狗龙王 UID100，槽2再次释放为 State2 / EmSetId -1，任务继续运行。

## 死亡检测的重要限制

青熊兽死亡、清理后，_QuestTargetEmDieUidList 仍只有 0 和 11600。该列表不能作为任意新怪种的通用死亡账本。原始目标仍只有 98 与 54，正式波次必须按新 UID 记录原生死亡事件，并将捕获单独覆盖。

## 结论边界

已实测：同一任务内注册不同怪种，走完整原生加载生成，以及复用已释放任务槽。不是简单复活原镰鼬龙王。

未验证：所有目标全灭后继续出怪、避免原生结算、循环回收顺序游标、长局内存增长、任意怪种、正式 RunSession/PT 联动。这里仍保留一只原目标避免提前结算；两次换怪发生于同一个任务，不能声称为两次独立任务复现。

原始 JSON 与 SHA256 分别归档在 first-arzuros、reused-slot-alive、after-second-kill 子目录。
