# 全灭续波与顺序游标循环（2026-10-27）

同一单人自定义任务900102，unique1994278460。停用大快照和逐帧调度探针，使用 inplace_cycle_probe.lua 做轻量实验；它仅在状态变化写出小型日志。

1. 开启 setQuestClear / setQuestClearSub 拦截和 checkQuestClear 结果覆盖，作用域限定本次任务unique。
2. 击杀最后原目标眠狗龙王UID100，捕获 questEnemyDie(type54,kind0)。尸体清理后Boss列表为空，全部任务槽释放，任务status仍为2，未结算。
3. 注册青熊兽记录119/UID11900，任务槽2重用；顺序表索引2设为2、之后清空，_BossSetCount回收到2，从RequestLoad5恢复。原生生成type60/UID11900，游标推进3。
4. 击杀UID11900，捕获questEnemyDie(type60,kind0)。再次全清后用同一方法注册120/UID12000，成功出场，游标再次2→3。
5. 击杀UID12000，再次捕获原生死亡事件。Reset scripts撤销实验结算拦截后，游戏立即进入原生60秒返回倒计时。

已证实：原目标全部死亡、空场后可继续原生生成；相同任务槽和顺序游标可连续回收两轮；通用questEnemyDie可捕获非原目标怪死亡，不能依赖目标死亡UID列表。

未证实：长局内存稳定、捕获、多种双怪配置、正式状态机/PT闭环。EnemySetInfo列表仍每只追加新记录，尚未回收；正式后端设置512条安全上限，不声称无限运行。
