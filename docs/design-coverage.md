# 策划条款与 Rise 实现范围

对照原案 `../mhw-moddev/docs/ref/design-v1.3.txt`，并保留后续已确认的改动：普通层三选一为 Single / Sequential / Simultaneous；同时双怪在同组合下 PT +15%、血量 -10%、伤害 -5%。以下区分实现和实机验收，不能用离线测试替代真实多人游戏。

|---|---|---|

## 不能写成“全部完成”的边界

- 原案包含《World》的煌黑龙、黑龙及专属地图机制。Rise 没有这些原生资产和 AI；现有工作使用 Rise 终盘怪与解锁链，不是完成这些怪物的移植。要字面实现该项，需要独立的模型、动画、AI、特效和机制项目，不能靠添加一个怪物 ID 解决。
- 极强掉落目前是临时武器/防具。原案中的随机稀有珠子、稀有护石及其限定穿戴还没有对应完整生产流程，不应拿武器/防具抽取替代验收。
- Native EnemySetInfo 与参数索引仍有安全上限。槽位可复用不代表已证明无限局内存稳定；现有上限是保护性停止，不应宣传无限局已验收。
- 自动发放装备不会替代原生换装界面；当前默认保留武器也与原案字面“禁止毕业装备”不同，来源是此前确认的 D1 方案。发布说明必须把这些选择讲清楚。

## 新一轮联机验收顺序

同版本、同配置 → 两人各选套装 → 房主选首波 → 每人开局购物 → 全员入队出发 → 首波各得 PT → 同场续波/个人掉落与购物 → 怪物造成三猫 → 原生 Failed=4 → 双方恢复 → 不 Reset 直接再开。再扩展捕获、3/4P、不同电脑及长局。普通完成回村与主动停止只算各自分支，不能代替三猫失败证据。

## 单人与多人对齐：交付门槛

“已实现”与“可发布为稳定多人”分别验收。多人复用单人的 RunCore、个人交易与恢复器，不另建一套影子商店；房主只裁决共享进度，任何原生发货只在收货玩家本机执行。

| 单人已有能力 | 多人接线 | 稳定发布还需要的证据 |
|---|---|---|
| 开局选套装、150PT、袋隔离 | 每人先 Preparing，个人备份成功才 ACK 入场；出发不重建钱包 | 同款原装备不被借用；中途失败、重载、进程重启及切角色都能识别恢复记录归属 |
| Single / Sequential / Simultaneous 与清波奖励 | 房主选波，各端相同 UID/槽/参数记录经 staged→commit→activate；各端累积 earned 差额记账 | 已补：队友普通武器命中及双端同步、原生捕获状态复制、同时双怪分别捕获/整波奖励。捕获用原生强制捕获触发，手动陷阱流程与更多武器仍需实测；重复帧不重发 PT/掉落保持门槛 |
| 波间购物、补满、四档抽取、单波服务 | 本机钱包和真实袋/装备箱；购买 busy 期间不确认下一波 | 主从分别买入，真实容量/限购/失败退款；会心钩子只影响本机角色；下一波生效和清波撤销 |
| 三猫、停止、原生结束后的重开 | 原生死亡共享；房主执行失败，所有本地恢复完成后退役旧会话 | 三猫必须 Failed=4，不能只看回村；房主/队友停止与报错各测一遍；不 Reset 直接再开 |
| 异常恢复 | 同一个装备/道具恢复器；任务实例和桥会话作隔离；交易未知仅在原资源恢复并保存、原生回村后封存，避免永久锁住重开 | 旧实例报文不能结束新局；恢复失败锁开局并给出原因，绝不能当作无备份重新覆盖。新增交易未知分支已有单引擎故障注入及多人应用层回归，仍待双端实机复测 |
| 数值编辑与预览 | 初次入场要求摘要一致；波间房主提案，经固定全队确认、原子保存后生效 | 当前波次和已生成选择保留；起始PT/猫车/装备等下局生效。双引擎通过，新增配置三/四端与官方跨电脑仍待实测，详见下文配置对齐 |

本机2/3/4真实引擎是上述原生路径的测试环境；模拟 Steam 不代替不同电脑官方 Steam。发布信息应分别列出已支持能力、已验收环境、已知限制，不能仅改掉“实验”文字便宣布完成。

结束记录分开保存工具结束原因（通关、猫车耗尽、主动停止或错误）和本机原生结果（成功、失败、仅返回或未知）。房主的 Finished 帧只同步原因，不构成队友原生失败证据；业务结束后仍读取本机绑定任务实例的结果，返回村庄不抹掉已记录结果。网页显示二者，结果冲突时提示下载日志。三猫验收仍需同实例的猫车递增与原生 Failed=4，不能只看 Finished、回村或主动失败。

## 剩余条款的实现方式

以下分项包含已落地的基础保护和仍待实现/强化部分，不能整节当作已经交付。优先级按玩家存档安全、多人闭环、内容扩充排序。

### 1. 恢复记录的持久身份与异常恢复

已落地（11月9日）：装备/道具袋记录绑定原生 GuildCardID 整数组件与 SnowSaveService 角色槽；名字仅展示。实机确认同角色跨冷启动标识稳定、不同角色不同，错角色与损坏记录锁住恢复/开局，保留原备份。道具袋 schema2 保存分类总数，处理空表变 null；缺非空分类或堆叠总数不符时拒绝写入。CLI 存档列表也改读原生角色槽数组，避免预览排序让名称与实际加载槽不一致。

本轮新增：schema3 保存原装备箱所有原有条目的完整属性指纹，以及临时件预留空槽与发放后指纹；包含强化、装饰品、颜色等已序列化字段。跨进程或同进程重新读档时，必须先核对完整原箱及所有额外条目，再恢复穿戴栏、道具袋并逐件回收；不按同款 ID 搜索删除。原生保存前先恢复，观察新角色保存的 busy→success、对应角色槽和身份，随后再次核对精确恢复记录及当前原状，才退役记录。缺失预期道具袋备份或记录变化时不认证。单人 reentry 的层间保存不触发整局恢复。

已取得一个独立的保存与冷启动通过样本：喜羊羊原有21件装备、原穿戴栏、非空普通物资与弹药袋，经停止任务、原生角色保存、退役记录、完整退出和加载同角色后逐字段一致。该项是保存专项，不算三猫；三猫原生失败证据单独核对。最终修复版双端任务900103 / unique -1395269277 已通过真实三猫（Play2/0→1→2→3、Failed4、None0，无 Success3），双方完成新原生角色保存、精确恢复并不重载进入下一场 Combat；随后把第三猫后的原生保存镜像按哈希原样加载，双方在恢复记录已 inactive 的情况下冷启动，完整装备属性、穿戴栏、非空普通物资/弹药袋均与各自开局前一致。测试镜像与后续清理存档分别归档，没有用重新打开的活动恢复记录修补冷启动结果。

恢复记录现通过 DLL 0.4.1 的受限 `write_recovery` 原语写入，只允许两种恢复记录文件名：同目录唯一临时文件 → 完整写入 → FlushFileBuffers → 关闭句柄 → MoveFileExW 替换并 write-through，随后 Lua 精确读回。失败保留原文件，不回退到 JSON 覆盖写；旧 DLL 缺少原语会在背包修改前拒绝准备，页面说明完整更新并重启。恢复轮询仍校验活数据，未变化的已恢复记录不重复落盘。

独立原生测试已覆盖目标锁定、写入中止、四阶段进程强杀以及并发完整性；实际 DLL→Lua 经过三次代际加载与写入读回，两个真实游戏引擎也完成个人准备/发放/恢复与保存。这些测试证明进程中断下不会暴露半份记录，不是对硬件断电、文件系统或存储介质故障的保证。实现依据为 [Windows 缓冲刷新](https://learn.microsoft.com/en-us/windows/win32/fileio/flushing-system-buffered-i-o-data-to-disk)和 [MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw) 的公开契约。

旧格式/无法证明归属的记录保留备份并拒绝自动迁移，不能靠删记录解除保护。自动保存关闭或恢复发生在上次原生保存之后时，需要在游戏原生菜单正常保存，页面会明确提示；不调用未验证的原生强制保存入口。

### 2. 多人结束协议与连续开局

用户停止、脚本异常、队伍变动、原生失败分别作为结束原因。活跃任务内的本地结束意图先锁定任务号与 unique 的失败完成拦截；队友发布当前 lobby/session 的结束请求，房主验证固定名册后排队原生失败。队友不得自行调用队伍结束接口。请求发送失败要重试，结束后的旧请求不得进入下一局。

原生已结束属于事实同步，不重新广播一个新的失败请求。双方分别等待结果、保存、实际村庄、个人恢复成功，再清旧 ACK 与计划、轮换 bridge，允许直接开新局。验收涵盖房主停止、队友停止、双方异常、第三猫发生在 Combat/Selecting、恢复待办失败后重试。每次记录明确的原生结束类型及任务实例。

未决交易可以阻塞选波，但不能阻塞同一局的结束消息。终局先校验本机任务实例；失败类意图固定完成拦截后才撤销波次策略，不由队友发起原生失败。终局仅同步累计账目，不触发新掉落或猫车写入。该补充已有六项定向回归及编译Lua验证；后续双端实测应在一端制造发货读回未知，另一端停止/报错，确认队友及时收尾、无额外发件、实际Failed、精确恢复且可不Reset重开。

结束身份从业务层一直传入原生适配器，入队及执行各比较任务号和unique，不能用调用时的最新实例替代原授权实例。缺失/非整数身份拒绝，负数实例保留；完成拦截也绑定同一预期身份。已补适配器和编译Lua回归，后续原生验收还需覆盖“旧快照形成后、执行前已换实例”的窗口，并确认新任务未被结束或拦截。

### 3. 联机策划配置对齐

已实现并双引擎验证：全队在准备前分别保存相同配置后，无需 Reset，新局的个人装备、起始PT、奖池、增益、奖励及节奏使用同一份最新规则；结束重建业务会话后保留该方案，不被内部联机任务号覆盖。完整原始命令SHA256同时补齐了嵌套配置变更的传输去重。早期证据位于本地 `docs/evidence/2026-11-09-config-live/`。

后续增加准备阶段的配置提案：房主发布经过 validateConfig 的规则版本、完整摘要和分块载荷，各端验证条目目录及协议兼容后显示差异并确认。全部 ACK 才生成首波与执行个人准备；不允许准备后换起始装备、PT和猫车规则。

局内调参已接上独立64 KiB配置通道和固定名册确认屏障，提案绑定 lobby/owner/session/serial/当前 waveToken/layer/新旧完整摘要；清波、全员集结且交易完成才由房主提交。已生效波次、已生成选项、已付费交易和已发掉落保持原规则。复用单人的字段冻结规则，起始PT、猫车上限、装备/抽取/增益/节奏留到下一局。各端原子保存和配置恢复记录独立于装备与物资恢复；Boot恢复错误不以默认值放行开局；仍保留原装备恢复能力。

最终双引擎样本任务965946750：仅改下一局起始PT（desired175/active150）进入配置代号1，再改药价/曲线进入代号2；ACK绑定配置代号，不能因有效摘要未变而接受旧确认。队友真实药袋0→1、230→227PT，房主230；后续倍率1.47，两端UID800眠狗龙王最大HP14156一致。随后本构建实际三猫Failed4/3、无Success3、正常保存并精确恢复原装/道具袋。独立文件锁专项证失败回村、开局保护及解锁后无Reset自动回滚；损坏配置记录启动时保留原装恢复协调器，不以默认方案放行。证据在本地 `docs/evidence/2026-11-09-config-barrier/`。新增配置三/四端有协议及编译Lua测试，仍不能沿用此前四端普通波次证据；官方跨电脑也待验收。

### 4. 稀有护石、珠子与临时穿戴

将当前 gacha 的发件事务扩展为装备种类适配器，统一 `preflight / reserve / grant / verify / equip / reclaim`，复用个人钱包与恢复记录。护石使用本版本原生护石生成/合法技能和槽上限；珠子使用 Rise 装饰品 ID 与合法槽位，不能照搬 World 的“五级珠子”概念。先读取并备份原装备珠子配置，再在本局允许装备范围内装卸，结束恢复并回收临时物品。

极强怪掉落由房主确认清波 token 与品质规则，每端记录一次领取事务；各端独立抽取与交付，不把主机箱索引发给队友。策划界面配置权重、技能范围、稀有度、是否允许指定装备，并显示原生校验失败。验收包含重复清波不重复发放、背包/装备箱满、已有同款、切装、退出与重启后的回收。

### 5. 长局出怪记录与场地清理

参数数组现按几何容量扩容，并保留已有参数和旧数组引用；四端实测编号106/107时容量128，下一波继续复用，不再每个新编号保留一份只多一项的数组。512记录/索引保护仍在。引擎其它出怪记录也占编号，本次读到109条；不能用自定义波次数推算记录数量，也没有据此证明无限局。

复用任务槽不等于回收 EnemySetInfo。先按层采样原生记录数、活对象数、参数长度和内存，确认死亡/捕获、尸体剥取结束、引擎销毁队列完成三个状态。研究引擎合法注销接口及所有索引引用；没有证据前不直接删列表或回绕 UID。

可安全注销后，采用全队清理屏障：各端报告旧 UID 无 actor、无待加载、无待同步引用；房主发布回收集合，各端执行并 ACK 相同记录摘要，然后发新 UID。身份仍单调，波次 token 永不复用。若原生无法安全回收，实施有提示的周期换图检查点：保留各自钱包、临时装备、掉落事务和共享层数，全员重新承接/入场后续跑，而不是无声结束本局。该路线应明确不符合“永不换图”的字面目标。验收跨当前512记录上限、持续多小时并包含捕获/同时怪及慢端。

场地效果单独按怪物能力建立清理适配：只清本波所属陷阱、弹体、地面效果；等待原生生命周期完成，不无差别销毁全地图组件。下一波前检测残留并写一条有界诊断。

### 6. Rise 怪池、极强单怪与机制

把每种候选怪的状态分为目录存在、加载成功、可战斗、机制完整、多人验收，网页怪池只默认展示达到对应发布门槛的条目。逐只验证进场点、体型、AI、寻路、普通伤害/捕获及特殊机制；记录具体模板和所需地图能力，不能以成功生成代替战斗验收。

Rise 终盘怪可通过现有 pools/ultimate/unlockChain 配置实现分层和前置解锁；极强怪仍硬性仅单怪，主从共用配置校验。World 煌黑/黑龙属于独立移植：资产许可与来源、模型动画、AI、音效特效、阶段与必杀、多人同步均需单独实现。现阶段的 Rise 替代方案与原案字面移植分开说明，不能声称填 ID 已完成。

### 7. 原装备限制与远程物资适配

保留用户确认的默认保留武器方案，同时提供策划开关：保留武器/指定入门武器、允许装备列表、是否卸护石/装饰品/猎虫。需要严格禁止毕业装时，应对每次原生换装作本机核验，越界仅拒绝或恢复最近合法装备；不得修改共享武器定义。网页必须说明本局规则，不能一边保留武器一边宣传禁止毕业武器。

按 Rise 真实配方重建弹药/素材对应表，区分原案 World 名称与 Rise 可用项、原生无限弹/瓶和真实携带上限；生成配置与编辑器都使用该表。主从分别验证购买补满、调和后再次补满、袋满、原生自带无限砥石、快速磨刀消耗鱼。Temporary 任务补给袋是否也清空应由规则明确并纳入备份，不能把目前只清 Normal/BulletBottle 称为“全部类别零物资”。
