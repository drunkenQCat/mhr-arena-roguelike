# 策划条款与 Rise 实现范围

对照原案 `../mhw-moddev/docs/ref/design-v1.3.txt`，并保留后续已确认的改动：普通层三选一为 Single / Sequential / Simultaneous；同时双怪在同组合下 PT +15%、血量 -10%、伤害 -5%。以下区分实现和实机验收，不能用离线测试替代真实多人游戏。

| 原案能力 | 当前实现及配置 | 验收/边界 |
|---|---|---|
| 同场续波、无限时长、拦截正常目标结算 | 原生 RequestLoad 状态机，逐端登记及 ACK/commit；inPlace 默认 | 本机两个引擎已跑单怪、顺序、同时与跨层循环 |
| 每人150 PT、首波奖励、开局商店 | Preparing 先准备个人套装与物资；出发时不重开钱包 | 双端购买药、装备抽取、首波80 PT、失败后新局通过 |
| 零物资、初始骨/铁套、护石卸除 | 个人持久恢复记录；五件独立临时防具，结束先恢复再回收 | 双端已实测；Regular 砥石等常驻道具保留，按 Rise 自带无限砥石处理 |
| 武器和猎虫方案 | startupRules.keepPlayerWeapon / weaponId / stripInsect | 延续已确认的默认“保留武器”；可由策划改指定武器，不能说默认禁止毕业武器已实现 |
| 三猫、付费恢复、原生失败/放弃/断线后清理 | 猫车按原生增量处理；房主恢复；结束实例保持完成拦截直到失败生效；回村后自动退役并可再开 | 三次真实受击、Failed=4、回村后同会话第二局通过；仍有活怪时注入同步错误后的失败回村也已通过 |
| 私人钱包、背包、装备抽取 | 原生发件读回、个人钱包；同款装备也新建，局末按条目身份回收 | 主从药品/抽取隔离通过；抽取后通过原生道具箱/帐篷换装 |
| 单波攻击、防御、会心 | 本机玩家属性/本机 actor 会心钩子；下一波消费、清波撤销 | 攻防回归与原生接线已覆盖；会心不再修改共享武器定义 |
| 全弹药与调和素材、单价/补满 | shop + item_ids；容量遵循游戏，先读实际缺口再一次发货 | 列表来自 Rise 映射，购买失败不扣款，不扩容背包 |
| 普通讨伐概率补给 | supplyDrops：每只怪判定、个人领取；弹药/素材/鱼，概率与权重可编辑 | 新配置默认35%；旧自定义配置需在编辑器启用，全队同步后重载 |
| 极强掉临时装备 | ultimate 清波本机 gacha_4 免费掉落，主从各自一次 | 协议/去重已覆盖；高层怪种仍需逐只实战，不把配置名字当作已验收 |
| 结算面板 | 清波数、累计收入、消费、余款、时长、恢复状态；自动回到 Idle 后保留上一局 | 不再把下一局的钱包当上一局结果；摘要保留在内存与事件日志 |
| 多人倍率、固定队伍和房主权威 | 2P / 3–4P 曲线、个人资源、共享猫车，固定名册 | 双引擎验收；3/4名真人和不同电脑官方 Steam 还需专项长局测试 |
| 分层、解锁、极强单怪 | pools / unlockChain / ultimate 规则及网页预览 | 采用现有 Rise 怪物目录；不会引入 World 不存在的怪物资产 |

## 不能写成“全部完成”的边界

- 原案包含《World》的煌黑龙、黑龙及专属地图机制。Rise 没有这些原生资产和 AI；现有工作使用 Rise 终盘怪与解锁链，不是完成这些怪物的移植。要字面实现该项，需要独立的模型、动画、AI、特效和机制项目，不能靠添加一个怪物 ID 解决。
- 极强掉落目前是临时武器/防具。原案中的随机稀有珠子、稀有护石及其限定穿戴还没有对应完整生产流程，不应拿武器/防具抽取替代验收。
- Native EnemySetInfo 与参数索引仍有安全上限。槽位可复用不代表已证明无限局内存稳定；现有上限是保护性停止，不应宣传无限局已验收。
- 自动发放装备不会替代原生换装界面；当前默认保留武器也与原案字面“禁止毕业装备”不同，来源是此前确认的 D1 方案。发布说明必须把这些选择讲清楚。

## 新一轮联机验收顺序

同版本、同配置 → 两人各选套装 → 房主选首波 → 每人开局购物 → 全员入队出发 → 首波各得 PT → 同场续波/个人掉落与购物 → 怪物造成三猫 → 原生 Failed=4 → 双方恢复 → 不 Reset 直接再开。再扩展捕获、3/4P、不同电脑及长局。普通完成回村与主动停止只算各自分支，不能代替三猫失败证据。
